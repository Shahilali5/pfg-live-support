PFG Live Support API & WebSocket Documentation

Complete reference manual for the PFG Live Support REST endpoints, real-time Socket.IO events, and white-label widget embedding system.

Bank-Grade Security Standards

This system strictly prohibits requesting or transmitting sensitive credentials including UPI PINs, CVVs, OTPs, or passwords. All user inputs are sanitized against XSS payloads and rate-limited.

Architecture Overview

PFG Live Support utilizes a hybrid HTTP + WebSocket duplex model:

  • REST API: Session bootstrap, historical retrieval, file uploads, agent authentication, and analytics.
  • Socket.IO (WSS): Real-time two-way messaging, typing indicators, presence, and read receipt updates.

Authentication & Authorization

Agent and administrator endpoints require a JSON Web Token (JWT) provided in the HTTP Authorization header:

Authorization: Bearer <YOUR_AGENT_JWT_TOKEN>

Customer endpoints are authenticated via a cryptographically random sessionToken stored securely in the browser's localStorage.

Single-Line Embed Script

You can embed PFG Live Support onto any website, payment checkout portal, or web app with a single script tag:

HTML Integration 
<script
  src="http://localhost:3000/widget.js"
  data-site-id="pfg_gateway_default"
  async>
</script>

Global Window JavaScript API

Interact with the live widget programmatically from your web application:

// Open chat window
window.PFGChat.open();

// Close chat window
window.PFGChat.close();

// Toggle visibility
window.PFGChat.toggle();

// Send automated message (e.g. on transaction failure)
window.PFGChat.sendMessage("Transaction failed: ERR_UPI_EXPIRED");

// Dynamically override branding configuration
window.PFGChat.setConfig({
  company_name: "Apex Pay",
  brand_color: "#059669",
  position: "left"
});

GET /api/admin/conversations

Lists all customer conversations with unread badges, last message previews, and filter criteria.

Headers: Authorization: Bearer <TOKEN>

Query Parameters: status (all/open/pending/resolved), department, search.

POST /api/upload

Uploads a payment receipt, screenshot, or document. Enforces strict MIME whitelist screening and 10MB file limit.

Request (multipart/form-data)

curl -X POST http://localhost:3000/api/upload \
  -F "file=@payment_receipt.png"

Response (200 OK)

{
  "success": true,
  "file": {
    "fileName": "payment_receipt.png",
    "fileUrl": "/uploads/pfg_1730658900_a81f3d.png",
    "fileSize": 245102,
    "mimeType": "image/png"
  }
}

Real-Time WebSocket Protocol (Socket.IO)

Socket.IO connects directly at ws://localhost:3000 with auto-reconnection and heartbeat detection.

Client to Server Events

Event NamePayloadDescription
customer:join_conversation { conversationId, sessionToken } Customer joins their private conversation room.
agent:join_conversation { conversationId } Agent joins a customer conversation room to monitor/reply.
message:send { conversationId, text, clientMsgId, attachment, isInternal } Sends a message. Deduplicated by clientMsgId.
typing:start { conversationId } Signals that the user started typing.
typing:stop { conversationId } Signals that the user stopped typing.
message:delivered { messageId, conversationId } Acknowledges message receipt.
conversation:seen { conversationId } Marks all unread messages as seen (blue checks).

Server to Client Broadcast Events

Event NamePayloadDescription
message:new { conversationId, message } Broadcasts newly posted message to conversation participants.
internal_note:new { conversationId, note } Sent only to support agents (never exposed to customers).
agent:typing { conversationId, agentName, isTyping } Indicates agent typing status.
customer:typing { conversationId, isTyping } Indicates customer typing status.
settings:updated { siteId, settings } Live white-label branding update broadcast to all open widgets.
messages:seen { conversationId, seenBy } Updates read receipts to blue double checks.
